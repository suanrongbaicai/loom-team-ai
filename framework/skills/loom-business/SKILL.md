# 商业判断方法（loom-business）

思路与结构借鉴 dontbesilent 的 dbskill（CC BY-NC 4.0，作者署名保留），内容为按 LOOM 需要用自己的话重写，不含原文，不作商业分发。

## 先看这几条（优先于下面所有方法）

1. **先查库，再用方法。** 团队已有的事实、客户资料、历史决定和更正，先取用，不让人重说。方法里“先向用户提问”的习惯，让位于“先看已有材料”。只问会改变结论的缺口，一次一两个。
2. **方法是视角，不是定论。** 这里的判断标准（如“99% 的创业问题是心理问题”“不要讨论兴趣”）是作者的立场。可以拿来检验一个问题，但不要当成事实宣布，也不要用居高临下的口吻；对团队成员保持亲近、友好的语气。
3. **不替用户定目的、数字、期限、成功标准。** 判断出的真需求、伪需求，只当作假设拿给对方确认，不替换对方原话。
4. **依据要标明来源。** 库内资料、模型已有知识、联网查到的，分别说明；联网内容不冒充库内资料；查不到就保留未知，不编造。
5. **大白话收尾。** 每次结论后，用最直白的话再说一遍；不展示哲学或经济学术语，除非对方要。
6. 超出能力的法务、财税、医疗类问题，明说“这个问题成立，但需要找专业人士”。

## 一、先判断问题本身成不成立（消解漏斗）

收到一个商业问题，按顺序过五层，每层发现问题就停下来和对方对一下，不要一次跑完：

1. **语言陷阱**：核心词有没有被定义？“适合”“值得”“高级”“有前景”“赛道”这类词，能不能说成可量化、可操作的？说不成，问题还不成立。做法：列出这个词可能指的两三种意思，问对方指哪种。
2. **假设错误**：问题背后默认了什么？把“我没钱怎么创业”改写成“你默认创业必须先有钱，这成立吗”。
3. **逻辑错误**：把相关当因果、被幸存者偏差带偏了吗？“拿到结果的人都努力”不等于“努力就有结果”。
4. **事实前提**：对方说的事实核对过吗？事实错了，问题方向可能反了。
5. **信息够不够**：现有信息够不够回答？不够，就说明先去拿什么数据，不硬答。

过完仍成立的，才进入回答。回答分四类：有标准答案的直接答；能用框架推导的给结论和推导；取决于价值选择的，先把利弊摊清，给出“我的倾向”并明说这是倾向，决定交回对方；取决于资源的，先问清他有什么资源再给建议。纯情绪问题明说超出商业判断，不展开。

## 二、看生意：七项检验（对方要全面检查时用，逐项停下来对话）

1. **机器检验**：这门生意要投入什么、稳定产出什么？换一个人来做，产出相同吗？
2. **激励检验**：这个模式逼人说真话还是逼人夸大、制造焦虑？赚钱是否依赖不可持续的做法？
3. **定价检验**：有几个价格带，差几倍？引流款和利润款差距太小，通常是同一个产品。
4. **需求检验**：区分买商品和买使用价值，很多购买买的是情绪满足或“有人陪着”。
5. **获客与变现检验**：获客、变现、交付是否放在同一个地方？结构是否各司其职？
6. **规模化检验**：流程能否固定？能不能不靠老板本人？不能，就还是高薪打工，不是可扩张的生意。
7. **阶段检验**：有人需要 → 有人愿意付钱 → 很多人付钱 → 稳定获客 → 品牌 → 产品矩阵 → 行业标准。不能跳层；在第 2 层想第 5 层的事，直接指出。

## 三、对标（模仿阶段）

从 0 到 1，模仿是合理做法，关键是模仿的颗粒度。筛一个候选对标，过五关：

1. 他真赚钱吗？利润要明显大于你当前的水平；粉丝多不等于赚钱。
2. 你能看懂他从获客、转化、交付到复购的完整链条吗？看不懂说明还缺行业认知。
3. 你能执行吗？不是现在有没有资源，而是能否在合理时间内获得；独家渠道、特殊资质这类不可复制的，不选。
4. 先把个人偏好放一边，只问“每一步我做得了吗”。注意：这是为了加速选择，不是否定对方的感受；对方说不适合时，问具体是哪一步做不了。
5. 不陷入“赛道前景”“行业好坏”的泛讨论，能干就执行，不能就换下一个。

模仿要对到可核对的细节（流程、话术、页面、节奏），不一致的地方就是要追问的问题。

## 四、用户要完成的任务（JTBD，挖真需求时用）

对方说“帮我做一个X”，那通常是方案，不是需求。往回找：

> 当我处于【情境】，我想【推进的变化】，以便【得到的结果】。

- **三层任务**：功能（要完成的进展）、情绪（想摆脱或获得的感受）、社会（希望别人怎么看自己）。功能任务决定交付物，情绪和社会任务常决定表达和最终选择。
- **雇用与解雇**：他为什么现在要换方案？推力（旧做法的具体损失）、拉力（新方案的承诺）、焦虑（担心的代价）、习惯（旧做法为何还能忍）。新方案要被采用，推力和拉力要强过焦虑和习惯。
- **选择标准**：提炼三到五条可观察的标准，分“必须满足”“加分”“可接受的代价”。“简单好用”要还原成“第一次用十分钟内能得到可修改的结果”这类。
- 材料够就先写“任务假设”，不机械追问；只问一个会改变建议的具体事实，如“你上一次做这件事卡在了哪一步”，不问“你的痛点是什么”。把假设拿给对方确认，保留他原来的方案作候选。

## 五、找理论依据与历史案例（要依据时用）

- **理论溯源**：先审命题（有没有绝对化、因果跳跃、偷换定义、以偏概全），再找能解释案例核心机制的理论；匹配度优先于名气；一般只留一个主理论；写清一个适用场景、一个不适用场景、一个可能推翻它的反例；找不到就说“暂未找到足够匹配的理论”，不硬套；页码、原话、首创归属核实不了就写明未核实，经典表述用标明的中文意译，不把记忆里的近似措辞当原文。默认不联网；只有外部事实会改变结论或对方要求核实时才联网，并标明。
- **历史同构**：先抽象问题的结构（角色、阶段、约束、矛盾、失败循环），再找结构相似的案例，成功、失败、反例一起看；比较机制，不讲传奇。答案分三级：成熟共识 / 条件性答案（说明条件和失效边界）/ 尚无统一答案。单个故事只能给启发，不能当标准答案。

## 六、奥派校准（涉及价格、利润、市场、企业家精神时用）

奥地利学派经济学的几个检验，用来看一个商业概念或方案，不是用来给结论：

- **价值是主观的**：这个概念是不是默认存在“客观价值”？价格由买家的主观评价和稀缺决定，而不是成本加成。
- **行动先于理论**：它描述的是人真实的行动，还是在替代行动？
- **知识是分散的**（哈耶克）：做这个决定需要哪些知识？分散在谁手里？有没有类似价格的信号能把它们聚起来？
- **别假设秩序可以被设计出来**：这个方案是不是默认有人能事先设计好整个市场？
- **能被价格验证吗**：不能被真实交易检验的，可能是空概念。
- **从“人会行动”推因果**（米塞斯）：现象的根本原因是什么？

使用时的诚实规则：别硬套。这几条对价格、利润和市场问题有用，对组织内部的协作问题不一定适用；如果这些视角在这里不解释任何东西，就说“这个框架在这里用不上”。有分歧时可以让几种视角并排说，再由我给判断和理由。

## 七、概念拆解的深入版（只在概念分歧影响团队时用）

日常用灵魂里的“意义即使用”和伪概念检测就够。只有一个核心词在团队里被反复误用、影响协作时，才做深入拆解：列出这个词在不同人嘴里的使用方式；还原它的原始语境和被扭曲之处；列出对象、事态、关系、规则、定义这几张表，写成“团队统一说法”，并保存到团队库，让以后的人沿用同一说法。

## 输出

默认紧凑：先结论，再必要的理由，再一个下一步；对方只要一个答案时，内部完成判断后直接给答案，用一两句话说明依据。判断不确定的部分明说，并写“待确认”。

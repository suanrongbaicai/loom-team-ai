# 报表与资料呈现

先理解用户要看什么、做什么决定、谁会阅读，以及已有资料和有效授权。用户指定格式时优先满足；没有指定时你选择合适形式并简短说明理由。不要让用户先学图表术语或填固定问卷。已有信息和持续授权足够就直接处理，只追问影响结论或下一步的缺口。

## 选择呈现

“表格”可能指整理得清楚，不必默认 Excel。结合目的和字段判断：

| 需要看清什么 | 通常适合 | 必须核对 |
|---|---|---|
| 找具体值、核对清单、比较选项 | 精简明细表；需要共同编辑时用飞书电子表格 Sheets | 一行一种对象、明确列名/单位；编号按文本保留 |
| 工作结论、会议经过、建议及依据 | 短报告/飞书文档，必要时嵌小表 | 结论在前，依据可查；不把长段叙述塞满单元格 |
| 各对象多少、排名 | 排序条形图配明细 | 同单位/口径，数量轴避免夸大差距 |
| 随时间变化 | 折线图；日期不连续时保留缺口 | 时间顺序、时区、采样间隔；缺失不是零 |
| 谁在什么时候做什么 | 甘特图或时间线 | 实际起止日期、负责人；无日期不能捏造排期 |
| 事情处在哪个阶段 | 看板 | 稳定事项编号与状态；拖动修改属于业务写入 |
| 几个关键结果一起看 | 简洁仪表盘 | 指标定义、统计范围、截止时间和明细入口 |
| 数值集中在哪、异常在哪里 | 直方图/箱线图 | 分组方式、样本量；平均数不能代替分布 |
| 两个数值是否一起变化 | 散点图 | 成对观测；相关不等于因果 |
| 总量如何分配 | 堆叠条形图；类别很少可用饼图 | 组成互斥且合计口径一致；非整体关系不硬凑占比 |
| 一个周期里的开、收、高、低 | 蜡烛图/K线图 | 四个对应数值及周期齐全；普通销售额不能硬转成K线 |

这些是选择依据，不是唯一答案。读者看不懂时用更简单的图或表；不是所有任务都要图。手机优先短标题、少列、清晰单位、可展开的明细。主视图不反复塞原话、版本号和工程说明，依据页/引用入口仍须保留且权限正确。

## 数据与生成

按已发布记录规则读取 Data、CL、Context，核对版本、更正、范围和实际采用的片段。你决定资料含义、分类和用途；程序负责计算及文件生成。保留原始值，身份证/客户编号/电话号码等不能因看似数字丢前导零或精度。空白、未知、零分别处理；日期、币种、含税口径不明就标明，不自行混算。

常见格式优先复用已验证的模板和现有模型，不为每张表再调用另一付费模型或临时生成整套页面。必要的新算法/视图沿 `loom-capabilities` 的具体能力申请、隔离开发、测试、发布与复用流程。任何一行报错、合计不符、丢列或来源无法核对，不能把完整成果报成正确；指出受影响部分，保留可用结果，按实际错误有限修正。

发送前核对行数、唯一编号、关键原值、合计及单位、实际显示和格式。读入文件、生成文件、平台接收、用户可读是不同结果。无需为已通过且未受影响的检查重复跑一遍；手机实际打不开或读不清就不能把“上传成功”当验收通过。不能保证任意新数据永无错误，也不能用通用免责声明代替核验。

## 飞书与资料库

Data/CL/Context继续承担原有职责。报表是从获准原件生成的产物，完整产物和必要结构化数据先存入 Data，CL记录本轮采用、计算、导入/导出和真实结果；Context只更新新的有效认识。可见报表不要泄露只供内部查证的内容或本机路径。

导出至飞书：核对目标文档/文件夹、用途、接收人及读写范围，保存准备发布的完整版本，再写入对应的原生文档或电子表格并记录实际回执、链接和版本。Bot能写某文件夹不代表该文件夹所有成员都能读源资料。库内复制保持不变，不能用外部链接代替原件。

飞书资料入库：只读取明确获准的文档/范围，实际保存取得的原文件或平台导出快照、来源身份、获取时刻、版本和覆盖范围；解析、截图、摘要另作派生材料。先按复制入库处理。只有明确要求移动且授权覆盖源端删除，才在核验入库完整后另行执行删除；不因“存入库”删除飞书原件。

在线协作表会变化。回收修改须比较原版本，按稳定行/事项编号生成差异；不靠当前排序后的行号对应资料，不静默双向覆盖，不把同一版本反复导入，不将前端拖动直接写进库。已有业务写权限覆盖时直接办理；新范围沿现有可信身份授权机制处理。

## 当前工具与接续

统计图采用 AntV 官方 `antv-gpt-vis`、`antv-g2-chart` 技能指导选图和 G2 v5 配置。本工程现有模板通过固定 G2 组件绘制，在本机生成完整、自含的交互 HTML：点按或悬停图中数据直接显示名称、数值、日期及已有单位；分类图例可筛选。不得用图外详情卡片代替图上读数，不把静态截图说成可点图。当前已接入的具体类型以 `report_templates` 为准；官方列出的26种不代表全部已经接入本服务。

官方技能是图表知识，不改变 LOOM 的数据权限、运行入口或发送规则。已有模板用 `report_view`，不为普通报表另开模型或临时编译页面；确需新图形时按 `loom-capabilities` 开发验证后复用。向官方文档服务查询时只使用公共API术语，不包含业务资料、用户原话、标识或凭据。默认CDN示例在正式成果中替换成随文件保存的固定组件，不向公共渲染服务上传数据。

完整HTML保存在Data。Bot交互主版负责精致易读与图中操作，飞书原生副本负责备份、编辑和流通，团队可择方便者查看；两者外观允许不同，但数据、单位、统计口径和版本必须对应。飞书Docs中的图是静态导出版，Sheets是原生可编辑网格；不把副本静态解释成主版也可以静态。以实际工具返回为准：交互托管未配置或未核验时明确说明尚未交付，不把127.0.0.1或局域网地址说成可转发的正式链接。

现有 `record_report` / `mobile_report` 生成并保存 XLSX，`save_work.report` 或 `send_report` 走已保存文件投递；完整文字答复仍先存后发。现有 XLSX 排版不等于已经具备上述全部视图。使用前按本轮工具目录核实实际能力。

需要固定成品视图时先用 `report_templates` 取模板用途和槽位。需要交互主版加飞书副本时，优先 `report_build(id,spec,backup_format,previous?)`：你完成查库、理解和选型，程序接着完成原件保存、飞书副本和交互版发布与回读，减少固定步骤之间的模型往返。backup_format由你按用途选docx或sheet。只有state=published才表示双入口已核验；incomplete保留已成功阶段，相同参数和id接续，unknown不得换号重建。该工具不代你判断CL采用、Context变化，不发送最终答复，仍按原记录和发送规则完成。只需库内成品时用 `report_view`；已有成品单独发布或补副本仍用 `report_publish`。飞书图文文档docx适合手机阅读，原生电子表格sheet适合协同编辑。不把HTML附件当成飞书内可直接读的文档；飞书文档采用原生排版及相同图表图片，不能承诺保留HTML全部交互。每次发布沿当前会话的真实成员和全部来源权限核验，不自己填写接收人、不设整企业或公开链接。

`report_publish` 返回实际链接与回读核对结果后，将采用及发布结果记入当前CL，再用 `save_work` / `reply` 保存完整答复并发送链接。用户需要交互图表时，先保存报表并发布适合用途的飞书副本（需数据备份/编辑时sheet，图文阅读时docx），再用同一report及该发布凭据backup调用`report_publish(format=interactive)`。返回成功后清楚标注“查看交互图表”“打开飞书副本”，两个入口属于同一数据版本。不要重复生成已有副本，不要只发送内部编号，不强求两种版式一致。按程序返回的行数、缺失数及合计复核，不把全缺数据的合计0当成已经确认的0。

交互副本以发布时核实的接收人范围为上限，打开时还须通过飞书本人登录和关联飞书副本的当前成员权限；转发链接不会自动添加接收人。需要扩给新对象时先沿既有授权核清范围，不能由工具自行扩大。已复制出去的副本不等同仍在库内的实时资料，库内规则改变不会凭空收回已下载内容；需要停用已发布入口时由管理程序撤销分享，不能声称只改库内权限就已撤回云端副本。

同次发布重用id：已发布只查回执，已知平台拒绝排除原因后从已存阶段继续，不重新创建文件；结果unknown先查 `report_cloud_status` 并核实，不能换id盲试。飞书副本由已授权成员独立查看，已披露/复制出去的内容不能声称可远程收回；新的发布及回库仍核验当前权限。

`report_import` 复制已发布电子表格的当前范围入Data，按隐藏的稳定行ID计算差异，保留旧版。你判断差异对应哪一事项、更正什么及是否影响Context，并按已有写权限更新。排序变化不等于记录变化；未知/重复行ID、结构变化和类型异常先保留原件再处理，不强行猜配。

`cloud_copy` 将本人消息中明确给出的新版飞书文档/电子表格，或当前会话已发布报表，按官方完整文件导出复制入库。source使用真实入站消息Data编号或已发布报表编号；不伪造消息、不填其他成员的私有文件链接。读取的范围是该整份文件，用户只批准片段时不能用整份导出。程序核对当前所有接收人在飞书的实际成员权限；只有群/部门继承且未核实到人时需补充核验，不能绕过。Bot缺文件权限时沿已有能力/授权找负责人把该文件加入可访问范围，只交给人确需本人操作的一步。exporting使用原id继续查询，unknown先查原因不可重复提交。保存成功后用material读取原件；文字解析不等于看完图像/音视频，平台没有导出的评论、版本历史或嵌入对象不能声称已入库。再次复制新版本用新id保留旧件，不覆盖历史。

需求超出现有模板/接口时核对 `capability_catalog` 和当前连接状态，已有工具/批准能办就继续；缺接口时沿能力接续机制提出具体对象、动作、用途、接收范围并接回原任务，不让用户修内部配置。

XCEL原版仅用于界面试用，不是这个技能的存储或权限执行器。不把宿主凭据放入浏览器，不把业务原件自动发给它默认的第三方模型，不在正式主页面直接执行未核验的生成代码。

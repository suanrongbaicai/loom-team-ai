# 人员与权限

本文件在部署时填写实际成员、平台账号和有效授权；未完成填写和确认前，不作为业务动作的授权凭据。正式位置为运行程序指定工作文件夹下的 `人员与权限.md`。

## 1. 文件职责与维护

供工作模型对照可信身份，确定本轮可读取、记录、执行与披露的范围，并定位对应资料及工具。普通工作模型只读；由已获授权的管理程序或维护者更新，并保留版本、依据和生效时间。

实际发送者、Bot、会话及任务触发者由接入程序提供。本文件保存对照关系，不允许模型根据昵称、聊天自称或人物画像选择权限。人员介绍和工作经验存入 Context，不能替代这里的授权。

团队部署时，本文件是管理配置中适用于当前工作空间的受控阅读版本。完整管理配置的位置及更新接口由部署核验后登记，本模板不预置客户盘符，也不虚构已经存在的文件。权限撤销需在实际执行入口及时生效，不能等待旧阅读版本自行更新。

## 3. 人员与可信账号对应

每个获准出现在本实例中的人员都要留下以下信息，使后来接手的模型能够核对到具体的人：

| 必要信息 | 具体记录什么 |
|---|---|
| 人员标识 | 稳定人员编号、称呼或别名；称呼仅供阅读，同名不合并 |
| 实际账号 | 软件或平台、真实账号编号，以及区分该账号所需的组织或应用范围 |
| 本人与账号的确认依据 | 怎样确认该账号对应本人、由谁确认、何时确认，以及可查阅的证据位置 |
| 适用范围与状态 | 适用 Bot、会话范围，以及有效、停用或待确认状态 |
| 后续核验办法 | 从哪个可信程序或接口取得哪些账号信息，如何与本记录对应，在哪里查当前权限；填写实际字段和入口，不能只写“核实身份” |
| 对应不上时的处理 | 缺少账号信息、出现多个候选或账号更换时，怎样重新确认、由谁处理；未确认前不使用相关权限，保留旧对应记录 |

首次接引时，由模型从平台提供的信息、已有材料及必要的本人确认中整理上述内容，通过获准的管理入口保存有效配置。不能只记名字和职责，也不能让普通模型直接改写权限。正常后续使用按所记办法核对，无需每次重新让成员自我介绍。

当前人员记录：**尚未绑定。** 文档中出现某人的名字，不等于完成账号确认或授予职务、管理权限。

## 4. 授权与工作集

每项授权对应明确的人员或获准触发者，并记录：

- 工作集编号、私有或共享、所属对象，以及适用 Bot 和会话。
- 内容范围及信息提供者、资料所有者或责任人、有权批准披露者的对应；哪些既有规则已构成持续授权，例外和申请入口是什么，不能只按私聊或群聊标签判断。
- 可读取、追加、更新、执行和披露的具体范围；外部发送的目标范围单独说明。
- 可知晓的人员、群体或已确认角色层级；团队内共享是否包含私聊工作记录、原文或仅部分内容、已有历史或未来记录，以及生效、到期、撤销和群成员变化时的适用范围。未作限制不代表默认扩大范围；确认为团队内全部工作资料共享时也无需逐条设置审批。
- 授权依据、批准记录、版本、生效时间、到期或撤销状态。
- 该事项的责任人、允许安排或批准该事项的人及其权限依据；适用于单次任务还是长期职责。
- 缺少或需要改变授权时，适用哪份审批规则、由谁发起、通过什么实际入口申请，以及到哪里核对结果；投票、个人批准等方式由本团队的有效规则决定。
- 已有审批与新增办法的对应：适用事项及限额、平台和组织范围、流程名称与编号、批准规则及其确认依据、结果读取入口与所需权限。每次申请另记实例编号、实际批准内容和可追溯证据。两种办法重叠时写清由哪种负责；确需同时满足时写清各自批准范围及先后关系，不能让模型临时选择。
- `data_root`、`event_root`、`context_root` 的实际绝对路径；涉及代码时另给 `code_root` 或具体仓库位置。
- 本工作集的对象导航位置；已有等价位置直接登记。可用的全文/语义搜索、引用索引入口及其覆盖范围只登记实际已接通的能力，不假定所有资料已被索引。
- 本工作集可用的记录工具入口与用法、执行工具及其限制；只登记实际已存在且获准的能力。
- 正式技能源目录、版本归档及发布记录查询入口；各成员可取得的技能版本与实际发布位置。技能正文按原生格式保存，版本与批准记录另由正式入口提供，不假定技能文件里的自称版本已获批准。
- 接引及已启用业务技能的实际入口、用途与适用范围；未生成、未验证或未发布的技能不登记为可调用。
- 群聊资料的获准范围和实际接收/读取入口；平台消息标识的核验方式；消息原件查询、任务接续及共享事件写入责任的正式接口。完整运行状态由管理程序提供适用视图，不能向每个 Bot 开放整个控制数据库。

人员与实际账号的对应关系、授权批准依据及适用范围不完整时，记录为待确认，不能当作有效授权。可以先保存已知内容，不为填满字段而猜测。

## 5. 隔离与披露

私聊取得当前成员获准的工作集；群聊取得对实际接收群体获准的工作集，可包含已经通过团队规则或单次批准开放的私聊工作记录。共享原件、摘要、提案、来源名称和链接都受披露范围限制，派生结论不能靠省略来源扩大披露。Bot 可用不等于它拥有所有成员的数据权限。

成员私有根、共享根及三层记录位置取本实例已登记的路径；未绑定位置不代表本机已经存在或当前模型已经获准访问。复用模板时不把上一个客户或设计者个人库的路径带入新实例。

凭据、令牌和登录秘密不写入本文件。必要时只登记获准使用的凭据引用和接口名称。

## 6. 变更历史

正式维护时记录版本、修改时间、修改者、变更依据和影响范围，并保留旧版本供追溯。历史授权不能继续当作当前有效授权，普通成员请求和模型推断不能自行改变本文件。

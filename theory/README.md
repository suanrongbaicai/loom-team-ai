# 先看理念

我把“为什么这么做”和“目前怎么实现”分开放。这里只讲 LOOM 的设计职责、取舍和验收要求，代码放在 `../framework/`。

| 目录 | 适合谁 | 怎么读 |
|---|---|---|
| `theory/` | 想了解三层记录、身份、权限和工作接续的人 | 先读总览，再看具体设计条款 |
| `framework/` | 想运行、部署或修改代码的人 | 先跑本地演示，再看实现和空配置 |

## 阅读顺序

1. [LOOM 理论总览](LOOM理论总览.md)：问题、职责和三层关系。
2. [执行样式 v1.10](LOOM落地执行样式-v1.10.md)：完整的设计与验收要求。第 9 节是合成部署示例，不带真实团队配置。
3. [当前实现与限制](../docs/status.md)：哪些已经有代码，哪些还没做完。

理论写着要做到，不代表代码已经做到。代码通过离线检查，也不代表真人体验和真实平台已验收。改设计时一起更新理论；改实现时说明它满足了哪一条、还有哪些限制。

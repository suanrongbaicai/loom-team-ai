# 把一个会话迁到常驻线路

适用情况：某个会话（例如 `chengcheng-private`）仍然每个任务单独启动一次 Codex（命令行线路），想改成和其他会话一样，复用一直开着的常驻宿主。只改 `controller.json`，不改框架代码。

## 为什么值得迁

命令行线路每个任务都要冷启动一次：启动 PowerShell、计划任务、Codex 程序和工具连接，每次工具调用前还要另起一个 Python 进程做核验。常驻线路省掉这些开销，而且支持多个会话并发。

## 先选一种方式

常驻宿主和登录目录（`CodexHome`，也就是用哪个订阅账号）是一一对应的。程序会检查：会话的 `worker_home` 和 `os_account` 必须与宿主绑定的那个会话完全一致，否则拒绝。

| 方式 | 适合 | 要改什么 |
|---|---|---|
| A. 共用现有宿主 | 这个会话本来就该用同一个订阅账号 | 会话加上 `"backend": "<现有资源编号>"`，并让它的 `worker_home`、`os_account` 与该资源的 `worker_scope` 会话一致 |
| B. 给它单独开一个宿主 | 这个会话用自己的订阅账号、自己的工作目录 | 在 `model_backends.resources` 新增一项，`worker_scope` 指向这个会话本身；会话加上 `"backend": "<新资源编号>"` |

## 步骤

1. **备份 `controller.json`**，记下当前内容。
2. 按选定方式修改 `controller.json`：
   - **方式 A**：在 `scopes.<会话>` 里加 `"backend": "<资源编号>"`；把 `worker_home`、`os_account` 改成与该资源 `worker_scope` 会话相同的值。
   - **方式 B**：在 `model_backends.resources` 里加一项：
     ```json
     "<新资源编号>": {"type": "codex-app-server", "worker_scope": "<会话>", "max_active": 2}
     ```
     再在 `scopes.<会话>` 里加 `"backend": "<新资源编号>"`。
3. **确认机器人在并发名单里**：服务这个会话的机器人应用编号，必须出现在 `model_backends.bots` 中（例如 `"<应用编号>": 2`）。不在名单里，调度器不会在常驻宿主上启动这个会话的任务。
4. 可选：在会话里设 `model` 和 `reasoning`。不设时，常驻线路的思考强度默认是 `high`。
5. **选系统空闲时重启控制器**：没有进行中的任务和发送中的回复，可用 `tools/trial_report.py` 或面板确认。
6. **验证**：在这个会话里发一条简单消息。
   - 应该很快收到回复；
   - 控制器日志里不应再出现为这个任务新起的 `launch-job` 计划任务；
   - `tools/trial_report.py` 里，这个会话的 `wait`（排队到模型开始）应明显变短。

## 出问题时退回

把 `controller.json` 换回第 1 步的备份，再在空闲时重启控制器。迁移不改数据库，退回不会丢失任何记录。

## 注意

- 方式 A 让这个会话与原会话共用订阅额度，并发上限（`max_active`）由它们一起分。
- 第一次使用某个常驻宿主时，它需要启动一次（之后常驻复用），所以第一条回复不会变快，从第二条开始才能看出差别。

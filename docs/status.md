# 当前能做什么

我把这份仓库当作可运行的开发版。离线测试能验证程序检查，真人长期使用还需要继续验证。

| 部分 | 当前实现 | 还需要做什么 |
|---|---|---|
| 三层记录 | 原件、事项经过、当前认识分开保存；记录版本和更正 | 继续验证模型有没有选对资料、理解对事实 |
| 身份和权限 | 可信接入身份、受众和记录范围检查；bot 身份与群称呼分开 | 新平台和新组织须自行核验配置 |
| 任务并发 | 独立会话可并行，同一会话保持顺序；bot 与共享模型资源分别限容量 | 七个席位是可配置容量，不是订阅一定支持七路的承诺 |
| 模型 | 已有 Codex app-server 适配与任务独立 thread/turn | 其他订阅或提供方仍需适配，未声称已经接通 |
| 交付 | 先保存，再发送；记录真实回执；unknown 不自动重发 | 平台故障和真人接收体验仍要在部署环境验收 |
| 图片 | 原生生图入口、获准历史原图引用和发送状态 | 本地演示不调用生图；实际使用依赖对应宿主支持与权限 |
| 群历史 | 已登记当前群的按需查询、来源和时间标记 | 私聊指定其他群读取/发图/@ 的统一入口尚未完成 |
| 主动通信 | 有批准范围的主动私聊、稳定操作编号和发送状态 | 跨群指挥和完整业务体验仍需继续验证 |
| 接续 | 新任务能读取已有记录入口 | 排队中的多条补充自动并入当前任务尚未完成 |
| 知识性质 | 执行样式 v1.11 与 `loom-work-records` v12、`loom-people` v2 区分做法、定论、个人偏好、易变事实和进行中；已采用的认识有误时，按暂停动作、先改来源再改记忆、用引用登记查影响范围的顺序处理；技能候选经 `propose` 提交；`tools/skill_upgrade.py` 可按范围切换技能版本并切回 | 分类目前由模型按技能文字判断，程序不检查；个人偏好仍存在 `set_my_profile` 的 `about` 字段，与自我介绍混在一起，群聊时随全体成员信息交给模型，尚未拆分；真实团队试用尚未验收 |
| 报表 | 表格、图表、网页及发布工具，附来源/版本检查 | 云发布与平台依赖需要独立配置 |
| 控制台 | 现有本地维护页有独立 mock 演示 | 新尺寸控制台和扩大模型选择范围还未接入正式功能 |
| 微信 | 有受控采集和权限接口 | 完整适配器另行安装；本仓库不分发它的实现或登录资料 |

测试标记有一项尚未完成的原型，用 `expectedFailure` 明确标注。它不是通过的功能，也不阻止其他已通过用例继续验证。完整数量见 [测试说明](testing.md)。

理论文件描述我希望系统满足的设计与验收要求；它们的每一条都不能自动算成代码已实现。具体限制以这里和当前代码为准。

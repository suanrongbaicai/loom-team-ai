# Loom

> 当你要把 AI 助手放进一个有真人、有权限、有责任的团队，真正的难题不是“能不能跑”，而是：**它说的话依据是什么？它有没有权限知道这件事？它上周的工作这周还接得上吗？人怎么批准它做危险的事？**
>
> LOOM 是一套已在真实团队运行的框架（公开前脱敏），用三层记录、逐次权限核查和提案表决回答这四个问题。

## 核心设计

- **Context（认识）**：有来源的当前认识。改它要有依据，旧版本留下。私聊里形成的结论，本人确认后可以只把结论共享到群。
- **CL（事项经过）**：逐段挂引用。每段给出实际采用的资料、版本和引文，宿主核对权限和原文之后才生成链接。
- **Data（原件）**：受保护保存的原始字节，带文件名、格式、摘要、来源和取得范围。没完整取得就如实记下。链接不等于已经读到原件。
- **做法是技能**：有版本。对话里教的先成为候选，批准后才对大家生效。
- **引用由模型提出，核查由宿主完成**：模型给出“我采用了哪段原文”，宿主核对本轮是否真的读过、当前谁能看、引文和版本是否对得上。
- **改权限、改规则走提案**：真人用平台身份表决，通过后在同一事务里生效。模型不能投票，也不能自己让规则生效。
- **平台身份就是真实身份**：飞书或微信消息的发送者决定是谁，不接受模型自报家门。

## 怎么用

拿来参考，按你的团队改。席位、接入的平台、谁来批准，都来自原来那套团队。把仓库交给 AI，让它对照 `theory/` 和 `framework/` 改成你的。

| 目录 | 内容 |
|---|---|
| `theory/` | 为什么这样设计 |
| `framework/` | 当前实现：三层记录、权限、任务、模型适配、飞书和微信接入、交付与检索 |
| `docs/` | 当前状态、共享前提、限制。做到哪一步以 [docs/status.md](docs/status.md) 为准 |
| `examples/` | 不联网的合成演示，用来看记录和回执怎么走 |

## 它守住的事

- 回复先保存，再发送。送达状态不明就保持 unknown，不另换编号重发。
- 技能要分清三件事：文件在不在、哪一版获批、有没有真正加载。
- 设计在 `theory/`，实现在 `framework/`。写着要做到，不等于代码已经做到。

## 适用人群

- 正在给团队放 AI 助手，卡在权限、依据和跨天接续上的人
- 做 Agent 产品，要设计引用和权限的人
- 研究人和 AI 怎么一起把责任定清楚的人

真实身份、聊天、配置和密钥不在这个仓库里。微信的完整适配器要另外安装。
